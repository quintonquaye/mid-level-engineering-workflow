# MDP-11 — Document local development and test commands

## Problem
A developer cloning the repository should be able to understand its purpose, install dependencies, run checks, and find the practice tickets without asking the author for instructions.

## Expected behavior
The README provides accurate setup and workflow instructions that a new contributor can follow from a clean checkout.

## Acceptance criteria
- [ ] Explain the purpose and architecture of the project.
- [ ] Document prerequisites.
- [ ] Document dependency installation.
- [ ] Document formatting, static analysis, and test commands.
- [ ] Explain the Issue → branch → tests → PR → CI workflow.
- [ ] Link to the practice issue index.
- [ ] Verify every command in the README is accurate.
- [ ] Keep documentation concise and avoid claiming checks passed unless you ran them.

## Investigation prompts
- What does a new contributor need to know before their first command?
- Which details belong in the README versus a focused guide?
- How will you verify the instructions from a clean working tree?

## Definition of done
A new developer can follow the documented setup and checks. The PR lists the commands you actually verified.
